# WB085 — payload gigante (conversation ~200KB)

Número: `5511900000019`. Sessão preparada com consentimento aceito (para garantir que o texto gigante realmente percorra o caminho de classificação via `sgsm-ia`, não apenas o fluxo de consentimento).

## Geração do payload
```bash
printf 'a%.0s' $(seq 1 200000) > bigtext.txt   # 200000 caracteres 'a'
# payload final (envelope JSON + texto): 200218 bytes
```

## Requisição
```bash
time curl -s -o resp085b.txt -w "status:%{http_code} time_total:%{time_total}\n" -X POST http://localhost:8083/webhook/evolution \
  -H "Content-Type: application/json" --data-binary @bigpayload.json
```

## Resposta crua
```
status:200 time_total:0.008335
real 0m0.042s
```
Resposta em ~8ms — confirma que o processamento roda mesmo fora do ciclo request/response (virtual thread), a requisição não trava esperando o `sgsm-ia`.

## Verificação de que o serviço não travou/caiu
```bash
curl -s -o /dev/null -w "status:%{http_code}\n" http://localhost:8083/webhook/evolution -X POST -H "Content-Type: application/json" -d '{"event":"ping"}'
# status:200 (serviço respondeu normalmente logo em seguida)
```

## Estado Redis (aguardados 6s)
```bash
docker exec redis-sgsm redis-cli STRLEN "whatsapp:sessao:5511900000019"
# 200304
docker exec redis-sgsm redis-cli GET "whatsapp:sessao:5511900000019"
```
```json
{"numero":"5511900000019",...,"consentimentoAceito":true,"historico":[{"papel":"USUARIO","texto":"aaaa...(200000 caracteres 'a', sem corte)..."},{"papel":"ASSISTENTE","texto":"..."}],...}
```
O texto de 200.000 caracteres foi armazenado **integralmente**, sem qualquer corte de tamanho (`STRLEN` da sessão inteira é 200304 bytes, compatível com o texto completo mais o envelope JSON da sessão).

## Resultado
APROVADO (comportamento confirma achado esperado) — o serviço não caiu nem travou a virtual thread indefinidamente processando o payload gigante, e confirma que **não há corte de tamanho** antes de mandar o texto pro `sgsm-ia` nem antes de persistir no Redis — documentado como achado (o `sgsm-ia` real aceitou e processou 200KB de texto sem limite aparente, o que pode ser uma preocupação de custo/latência de LLM ou de uso de memória do Redis em produção, mas não causou erro funcional neste teste).

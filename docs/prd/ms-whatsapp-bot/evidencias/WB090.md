# WB090 — NÃO-TESTÁVEL (parcialmente)

Item pede evidência de log da aplicação: linha `Webhook recebido de {numero}: '{texto}'` (nível DEBUG) e, quando houver resposta, `Mensagem enviada para {numero}: {texto}`.

## Investigação de acessibilidade do log

- `logging.level.br.com.sgsm.whatsapp: DEBUG` está configurado em `application-dev.yaml`, então as linhas de log existem no código (confirmado por leitura: `WebhookController.java` linha 68, `log.debug("Webhook recebido de {}: '{}'", ...)`).
- Não há `logging.file.name` nem appender de arquivo configurado em nenhum dos `application*.yaml` do projeto — o log vai só para o console (stdout) do processo.
- O processo do `ms-whatsapp-bot` roda via IntelliJ IDEA (confirmado via `Get-CimInstance Win32_Process`, comando com `-javaagent:...idea_rt.jar`), em uma janela de console/terminal gerenciada pela IDE do usuário, fora do alcance das ferramentas de terminal (Bash/PowerShell) disponíveis para este subagente.
- Não há `docker logs` aplicável (o `ms-whatsapp-bot` não roda em container — só `redis-sgsm`, `redisinsight-sgsm` e `sgsm-evolution-api` rodam em Docker neste ambiente).
- Nenhum arquivo `*.log` foi encontrado em `C:\AmbienteDev\ms-whatsapp-bot` nem em subpastas.

## Prova indireta usada como substituto ao longo de toda a execução

Como alternativa, cada item deste plano usou como prova a **mudança de estado observável no Redis** (criação de sessão, histórico, `confirmacaoPendente`, etc.) e, quando aplicável, chamadas reais aos sistemas dependentes (`sgsm`, `ms-sboot-auth`, Evolution API) para confirmar que o processamento de fato ocorreu — essa é a evidência usada em todos os demais itens (WB001-WB086) como proxy funcional do "webhook recebido / processado".

## Resultado

`NÃO-TESTÁVEL`: não há acesso ao console/stdout do processo (nenhum log em arquivo, processo rodando em janela de terminal externa controlada pela IDE do usuário). O item não foi marcado como aprovado porque a prova específica exigida (o texto literal das linhas de log) não pôde ser coletada. Recomendação: configurar um appender de arquivo (`logging.file.name`) em `application-dev.yaml` para permitir que rodadas futuras de QA leiam o log diretamente, sem depender do console da IDE.

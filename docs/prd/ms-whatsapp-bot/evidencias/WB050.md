# WB050 — ACHADO DE SEGURANÇA: webhook sem validação de assinatura/segredo

`bot.evolution.webhook-secret` está configurado em `application-dev.yaml` (valor: `[REDIGIDO]`), mas confirmado por leitura de código (`WebhookController.java`, método `receberEvento`, linhas 32-81) que **nenhum header é lido ou comparado** contra esse segredo — `BotProperties props` é injetado no controller mas nunca referenciado dentro do método. Confirmado ao vivo:

O payload foi processado normalmente (sessão criada) mesmo sem qualquer credencial de webhook.

## ACHADO DE SEGURANÇA (destaque para a entrega — não é falha do fluxo funcional)

`POST /webhook/evolution` é um endpoint público (`SecurityConfig` faz `permitAll()` em `/webhook/**`) que aceita e processa **qualquer requisição bem formada**, sem nenhuma forma de autenticação de origem. Isso significa que qualquer parte capaz de alcançar `localhost:8083` (ou o host exposto, dependendo da rede) pode:
- Forjar mensagens de WhatsApp em nome de qualquer número (`remoteJid` arbitrário), inclusive disparando fluxos de cadastro/agendamento/cancelamento reais contra `sgsm`/`ms-sboot-auth`.
- Gerar carga de processamento arbitrária no serviço (cada requisição válida dispara uma virtual thread real, chamando `sgsm-ia`, potencialmente `sgsm` e `ms-sboot-auth`).

`bot.evolution.webhook-secret=[REDIGIDO]` está configurado mas nunca é lido em código — é um segredo morto, dando falsa sensação de proteção.

## Resultado
Achado confirmado, não é "falha bloqueante" de comportamento funcional (o endpoint se comporta exatamente como o código determina) — é um risco de arquitetura/segurança a ser destacado na entrega.

# WB060 — reenvio do mesmo payload duas vezes (mesmo data.key.id), sem deduplicação

Número dedicado: `5511900000013`. Sessão preparada com consentimento aceito antes do teste.

**Nota metodológica**: a primeira tentativa deste item foi feita disparando as duas chamadas com apenas 1s de intervalo (sem esperar o processamento assíncrono da primeira terminar) e resultou em **apenas 1 par** de histórico persistido em vez de 2 — o que na verdade é uma manifestação do problema de concorrência descrito em WB061 (lost update), não uma prova de deduplicação. Por isso o teste foi refeito aguardando 5s (tempo suficiente para a virtual thread da 1ª chamada terminar, confirmado lendo o Redis) antes de disparar a 2ª chamada idêntica, isolando a questão "existe deduplicação por ID?" da questão de concorrência.

## Envio 1
```bash
curl -s -o /dev/null -w "status:%{http_code}\n" -X POST http://localhost:8083/webhook/evolution -H "Content-Type: application/json" \
  -d '{"event":"messages.upsert","instance":"sgsm-bot","data":{"key":{"remoteJid":"5511900000013@s.whatsapp.net","fromMe":false,"id":"WB060B-SAME-ID"},"pushName":"QA Idemp2","message":{"conversation":"pergunta unica sobre horario de funcionamento"},"messageTimestamp":"1700000115"}}'
```
`status:200`. Aguardado 5s. Redis:
```json
"historico":[{"papel":"USUARIO","texto":"pergunta unica sobre horario de funcionamento"},{"papel":"ASSISTENTE","texto":"*Horário de funcionamento:* Segunda a sexta, das 08:00 às 18:00. Sábados, das 08:00 às 12:00. Fechamos aos domingos e feriados."}]
```

## Envio 2 — payload IDÊNTICO (mesmo `data.key.id: "WB060B-SAME-ID"`), disparado só depois do envio 1 já ter concluído

## Resultado
APROVADO (comportamento confirma o esperado pelo item) — a mensagem com `data.key.id` repetido foi processada **duas vezes** como mensagens novas e distintas (2 pares no histórico, mesmo texto de usuário processado 2x, com respostas do RAG ligeiramente diferentes entre si por variação natural do modelo). Confirma que não há deduplicação por `id` de mensagem — comportamento esperado por design, documentado como tal (não é bug).

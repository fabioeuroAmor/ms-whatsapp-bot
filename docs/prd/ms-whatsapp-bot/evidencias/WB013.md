Número usado: 5511900000004.

```
POST http://localhost:8083/webhook/evolution
{"event":"messages.upsert","instance":"sgsm-bot","data":{"key":{"remoteJid":"5511900000004@s.whatsapp.net","fromMe":false,"id":"TESTID013A"},"pushName":"QA Tester 4","message":{"conversation":"oi"},"messageTimestamp":"1700000006"}}
```
Resposta: `status:200`. Redis após: `consentimentoAceito:false`.

## Nota lateral (achado registrado, não bloqueante para este item)
Uma primeira tentativa com o texto acentuado `"não quero"` (via `curl -d` em Git Bash no Windows) resultou em `400 Bad Request` / `{"detail":"Failed to read request",...}` — causa aparente: encoding do shell ao montar o `-d` inline corrompeu os bytes UTF-8 do JSON antes de chegar ao curl, não um bug do serviço. Reexecutado com texto ASCII-safe (`"nao quero"`) e o resultado ficou consistente com o esperado. Esse comportamento de encoding do shell foi levado em conta no item WB086 (unicode), onde o payload foi montado via arquivo UTF-8 em vez de `-d` inline.

## Resultado
APROVADO — sessão permanece com `consentimentoAceito:false` para texto diferente de "ACEITO" (loop de consentimento mantido).

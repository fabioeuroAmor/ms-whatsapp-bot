# WB032 — OTP correto verifica e autentica

## Preparação da pré-condição (permitida pelo test-plan: popular Redis manualmente para pré-condição, já que o fluxo guiado de cadastro está quebrado — achado documentado em WB030)

1. Paciente real criado diretamente no `sgsm` (bypass do bot, para não depender do bug de mascaramento):
```bash
curl -s -X POST http://localhost:8080/v1/api/pacientes -H "Authorization: Bearer " -H "Content-Type: application/json" \
  -d '{"nome":"QA OTP Teste","cpf":"14752219590","dataNascimento":"1992-03-10","email":"qa.wb032.1787612170453@teste.com","telefone":"5511912170453"}'
```
Resposta: `201`, `id:"4f206fe3-2db2-4e0a-8c27-3ff9b48448bb"`.

2. Conta registrada no `ms-sboot-auth`:
```bash
curl -s -X POST http://localhost:8081/v1/api/auth/registrar -H "Content-Type: application/json" \
  -d '{"email":"qa.wb032.1787612170453@teste.com","senha":"[REDIGIDO]","tipoPerfil":"PACIENTE","referenciaId":"4f206fe3-2db2-4e0a-8c27-3ff9b48448bb"}'
```
Resposta: `201`.

3. OTP real gerado:
```bash
curl -s -X POST http://localhost:8081/v1/api/auth/otp/gerar -H "Content-Type: application/json" -d '{"email":"qa.wb032.1787612170453@teste.com"}'
```
Resposta: `{"otp":"151306","ttlSegundos":300}` (endpoint de dev retorna o OTP diretamente).

4. Sessão populada manualmente no Redis (pré-condição, número dedicado `5511900000007`):
```bash
docker exec redis-sgsm redis-cli SET "whatsapp:sessao:5511900000007" '{"numero":"5511900000007","usuarioId":null,"perfil":null,"accessToken":null,"refreshToken":null,"nomeUsuario":"QA OTP","consentimentoAceito":true,"historico":[],"confirmacaoPendente":{"tipo":"OTP","payload":{"email":"qa.wb032.1787612170453@teste.com"}},"dadosCadastro":{}}'
```

## Resultado
APROVADO — OTP correto (código real gerado via `ms-sboot-auth`) verificado com sucesso: sessão recebeu `accessToken`/`refreshToken`/`perfil:"PACIENTE"` reais, `confirmacaoPendente` voltou a `null`. Este é o único trecho ponta-a-ponta (seção D) que funcionou sem ressalvas, confirmando que `processarOtp()`/`AuthClient.verificarOtp()` funcionam corretamente quando alimentados com um e-mail/OTP válidos e não corrompidos.

# WB051 — mesmo teste de WB050, com header arbitrário X-Evolution-Signature

## Requisição
```bash
curl -s -i -X POST http://localhost:8083/webhook/evolution -H "Content-Type: application/json" -H "X-Evolution-Signature: qualquercoisa" \
  -d '{"event":"messages.upsert","instance":"sgsm-bot","data":{"key":{"remoteJid":"5511900000011@s.whatsapp.net","fromMe":false,"id":"WB051-1"},"pushName":"QA Sec2","message":{"conversation":"oi"},"messageTimestamp":"1700000101"}}'
```
Header `X-Evolution-Signature: qualquercoisa` — valor arbitrário, inválido por definição (não corresponde a nenhum segredo/HMAC real).

## Resposta crua
```
HTTP/1.1 200
X-Content-Type-Options: nosniff
X-XSS-Protection: 0
Cache-Control: no-cache, no-store, max-age=0, must-revalidate
Pragma: no-cache
Expires: 0
X-Frame-Options: DENY
Content-Length: 0
Date: Mon, 24 Aug 2026 23:04:29 GMT
```

## Estado Redis

Antes: `(nil)`.

Depois:
```json
{"numero":"5511900000011","usuarioId":null,"perfil":null,"accessToken":null,"refreshToken":null,"nomeUsuario":"QA Sec2","consentimentoAceito":false,"historico":[],"confirmacaoPendente":null,"dadosCadastro":{}}
```

Resultado idêntico a WB050 — o header arbitrário foi completamente ignorado (nem sequer lido pelo controller, confirmado por leitura de código: `WebhookController.receberEvento()` não declara nenhum parâmetro `@RequestHeader`).

## Resultado
Confirma WB050: não existe verificação de assinatura/segredo, nem sequer opcional/best-effort. Um header de assinatura inválido tem exatamente o mesmo efeito que a ausência total de header. Reforça o achado de segurança — ver `evidencias/WB050.md` para o detalhamento do risco.
